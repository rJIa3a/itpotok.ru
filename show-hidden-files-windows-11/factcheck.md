# Фактчекинг

Дата сверки: 16 октября 2026 года. Запрос: «как показать скрытые папки в windows 11», точная частотность из контент-плана — 839. Практический прогон переключателей на тестовой Windows не выполнен; материал сверён с Microsoft, меню — с собственным русским интерфейсом Проводника.

| Утверждение | Первичный источник и результат |
|---|---|
| Проводник открывается Win + E; скрытые элементы включаются в меню представления | [Microsoft Support: Проводник в Windows](https://support.microsoft.com/ru-ru/windows/experience/fileexplorer/file-explorer-in-windows). Страница относится к Windows 11 и Windows 10, содержит отдельные секции; машинный перевод названий местами некорректен. Название «Просмотреть» подтверждено своим русским кадром. |
| В параметрах папок на вкладке «Вид» есть выбор показа скрытых файлов, папок и дисков | Та же справка Microsoft. Указан путь «…» → «Параметры» в текущем Проводнике; открытие окна «Параметры папок» и вкладка «Вид» обнаружены в дереве доступности. Само содержимое вкладки снять достоверно не удалось. |
| Защищённые системные файлы требуют дополнительного флажка | [Microsoft Learn: Correct disk space problems on NTFS volumes](https://learn.microsoft.com/en-us/troubleshoot/windows-server/backup-and-storage/disk-space-problems-on-ntfs-volumes), раздел File attributes or NTFS permissions. Это документация Windows Server: используется для принципа двух независимых настроек и подтверждения предупреждения, старый путь меню Tools не перенесён в инструкцию Windows 11. |
| Hidden и System — разные атрибуты | [File Attribute Constants](https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants): Hidden исключает объект из обычного списка, System обозначает использование ОС. Показ не снимает атрибут. |
| Видимость не даёт права чтения и изменения | [File Security and Access Rights](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights). Доступ регулируют security descriptor и ACL. В статье не предлагается менять владельца системных каталогов. |
| %APPDATA% указывает на Roaming текущего профиля | [Recognized environment variables](https://learn.microsoft.com/en-us/windows/deployment/usmt/usmt-recognized-environment-variables), APPDATA / CSIDL_APPDATA. Это типовой путь; перенаправление профиля практически не проверялось. |

## Конкурент и существующие статьи

[Материал remontka.pro](https://remontka.pro/show-hide-hidden-system-files-folders-windows-11/) получен обычным HTTP-запросом, HTTP 200. Дата статьи на странице — 14.08.2024. Конкурент рассматривает меню, параметры папок, системные файлы и настройки разработчика. В нашей статье оставлены два понятных штатных пути, добавлены проверка на пустой личной папке, точный возврат, различие атрибута и разрешений, диагностика отсутствия объекта. Реестр и настройки разработчика не нужны для заявленной задачи.

Поиск опубликованных записей WordPress по «скрыт» сохранил результаты в duplicate-check.json. Близкие заголовки: ID 8136 — Windows 8; ID 6511 и 3237 — Windows 7. Статьи на тот же запрос для Windows 11 не обнаружено. Создана новая запись 12112 с английским slug show-hidden-files-windows-11. Старые записи не изменены.

## Границы проверки

- Собственный русский кадр показывает реальный пункт «Скрытые элементы» с галочкой. Изменение флажков и эксперимент с тестовой папкой не проводились; текст описывает способ проверки для читателя.
- Съёмка вкладки «Вид» не завершена: Computer Use вернул несогласованные визуальное состояние и дерево, затем ошибку `element 215 is not available in cached app state for explorer.exe`. Подмена кадра макетом или английским снимком не выполнялась.
- Не проверялись управляемый организацией ПК, все сборки Windows 11, другие профили и состояния после перезагрузки. Установка атрибута на реальных системных файлах не выполнялась.
- Статус WordPress, равенство тела и отрывка, назначенная обложка и отсутствие видимого шорткода проверяются API; визуальные результаты — в evidence и publication-check.json.
