Если при запуске программы отсутствует MSVCP110.dll или MSVCR110.dll, установите либо восстановите Microsoft Visual C++ Redistributable для Visual Studio 2012 Update 4 с сайта Microsoft. Выбирайте пакет по разрядности программы: x86 для 32-разрядной, x64 для 64-разрядной. На 64-разрядной Windows могут понадобиться оба пакета.

Что это за файлы и почему появляется ошибка

Это библиотеки среды выполнения Microsoft Visual C++ 2012: MSVCR110.dll относится к библиотеке C, MSVCP110.dll — к стандартной библиотеке C++. Они нужны приложениям, которые используют эти компоненты. Число 110 указывает на поколение Visual C++ 11.0, связанное с Visual Studio 2012.

Сообщение «запуск программы невозможен» или «не удалось продолжить выполнение кода» означает, что приложение не смогло загрузить нужную библиотеку. Пакет мог не установиться вместе с программой, быть удалён или повреждён. Иногда причина находится в самой программе: например, она загружает несовместимую копию DLL из своей папки.

Установка самого Visual Studio не требуется. Современный пакет Visual C++ v14 также не заменяет версию 2012: старые поколения устанавливаются отдельно. Не удаляйте остальные Visual C++ из списка приложений — они могут требоваться другим программам.

Как выбрать x86 или x64

Узнайте разрядность проблемной программы на странице разработчика или в её требованиях. Разрядность Windows показывает, какие приложения система может запускать, но не определяет разрядность каждого установленного приложения.

СитуацияЧто выбратьПочему
32-разрядная программа на обычном ПК с Windows x64vcredist_x86.exeЕй нужны 32-разрядные библиотеки, даже если система 64-разрядная.
64-разрядная программа на Windows x64vcredist_x64.exeБиблиотеки должны соответствовать приложению.
Разрядность неизвестна, Windows x64x86 и x64 по очередиТак вы обеспечите обе среды; пакет x64 сам по себе не покрывает x86.
Windows x86, например 32-разрядная Windows 10Только x86Пакет x64 и 64-разрядное приложение на такой системе не работают.

В Windows 11 и 10 тип системы можно посмотреть в Параметры → Система → О системе. На компьютере с ARM ориентируйтесь на требования разработчика конкретной программы. Файл vcredist_arm.exe со страницы 2012 года не является современным ARM64-пакетом для Windows 11.

Скачать и установить официальный пакет

  1. Сохраните документы и закройте проблемную программу.
  2. Откройте страницу Visual C++ для Visual Studio 2012 Update 4. Проверьте название: нужна версия 2012, а не 2013 или современный v14.
  3. Выберите русский язык и нажмите Загрузить. Отметьте vcredist_x86.exe, vcredist_x64.exe либо оба файла по таблице выше. Нажмите Загрузить в окне выбора.
  1. Откройте свойства скачанного EXE-файла через контекстное меню. На вкладке Цифровые подписи проверьте подпись Microsoft Corporation и её действительность через сведения о подписи. Если подпись отсутствует или недействительна, не запускайте файл: скачайте его повторно с официальной страницы.
  2. Запустите установщик, прочитайте условия и выполните установку. Для изменения компонентов потребуются права администратора. Если нужны оба пакета, дождитесь завершения первого, затем запустите второй.
  3. Перезагрузите компьютер, если установщик попросит об этом. Затем снова запустите ту же программу и выполните действие, на котором появлялась ошибка.

На 22 октября 2026 года русская страница и оба EXE-файла доступны. Если страница перестанет открываться, используйте раздел Visual Studio 2012 (VC++ 11.0) Update 4 в официальном списке загрузок Microsoft. Прямые ссылки в этом разделе ведут на англоязычные пакеты версии 11.0.61030.0; язык установщика не меняет нужную приложению разрядность.

Поддержка Visual Studio 2012 завершилась 10 января 2023 года. На старой странице загрузки Windows 10 и 11 не перечислены в системных требованиях. Доступность установщика сама по себе не означает официальную поддержку современной Windows или совместимость вашей программы. Если разработчик предлагает обновлённую версию приложения, проверьте её требования.

Если Visual C++ 2012 уже установлен

Сначала восстановите именно пакет 2012 нужной разрядности. Наличие Visual C++ 2015–2022 или другой версии этого не заменяет.

  1. Нажмите Win + R, введите appwiz.cpl и нажмите Enter. Откроется список «Программы и компоненты».
  2. Найдите Microsoft Visual C++ 2012 Redistributable с нужной пометкой (x86) или (x64). Запишите его версию и разрядность.
  3. Откройте изменение выбранного пакета. Если установщик предлагает восстановление, выберите его и дождитесь завершения. В разных языковых версиях действие может называться «Восстановить» или Repair.
  4. Если восстановление недоступно из списка, повторно запустите официальный установщик той же разрядности и используйте восстановление, если оно предложено.

Если восстановление завершилось ошибкой, запишите её код. Не удаляйте все пакеты Visual C++ подряд. Переустановка конкретного пакета 2012 — следующий вариант: заранее скачайте его официальный установщик, закройте приложения, удалите только выбранный пакет и установите его заново. Пока он удалён, другие зависимые программы могут не запускаться.

Установка не требует ручного копирования DLL или изменения реестра. Для возврата после пробной установки новый пакет можно удалить через «Программы и компоненты», но это снова лишит зависимые приложения библиотек. Восстановление не имеет отдельной кнопки отмены; если переустановка не удалась, верните пакет официальным установщиком и разберите ошибку установки.

Как проверить результат и что делать, если ошибка осталась

Проверьте два признака: пакет нужной разрядности появился в списке установленных программ, а приложение запускается и проходит прежний проблемный шаг без сообщения об MSVCP110.dll или MSVCR110.dll. Одна запись в списке ещё не доказывает, что проблема устранена.

  • Установлен только x64, а ошибка осталась. Уточните разрядность приложения и его запускающего модуля. Если у игры 32-разрядный запускатель, ему нужен x86.
  • Сообщение теперь называет MSVCP120.dll, MSVCR100.dll или другой файл. Это другая зависимость. Подберите соответствующий компонент по инструкции разработчика; не переименовывайте MSVCP110.dll в файл с другим номером.
  • Появилась ошибка точки входа или 0xc000007b. Простое отсутствие библиотеки больше не единственное объяснение. Возможны несовместимые файлы программы или смешение разрядностей. Восстановите файлы приложения средствами его установщика или игрового клиента, уберите внесённые вами модификации по их инструкции. Перед переустановкой сохраните пользовательские данные.
  • Ошибка только у одной программы. Проверьте её обновления и восстановление файлов. Если вы ранее вручную добавили DLL в её папку, не заменяйте системные библиотеки: верните состав приложения через проверку файлов или переустановку из доверенного источника.
  • Антивирус сообщил об удалении файла. Изучите обнаружение и источник приложения. Не отключайте защиту и не возвращайте файл из карантина без выяснения причины.
  • Установщик сообщает, что уже есть другая версия, либо не завершается. Сверьте год и архитектуру, попробуйте восстановление существующего пакета. Сохраните код ошибки и журнал для поддержки приложения. Повторные запуски разных сборок пакета вслепую не объяснят причину.

Если восстановление пакета и файлов программы не помогло, передайте разработчику точное имя DLL, полный текст ошибки, разрядность приложения, версию Windows и установленных пакетов 2012. Это позволит отличить недостающий компонент от ошибки сборки или несовместимости приложения.

Почему не стоит скачивать одну DLL и запускать regsvr32

Отдельный файл со случайного сайта может оказаться вредоносным, другой версии или разрядности. Копирование в System32, SysWOW64 или папку игры не устанавливает весь набор зависимостей и может заставить приложение загрузить неподходящую библиотеку.

regsvr32 предназначен для регистрации поддерживающих её компонентов, а не для установки среды Visual C++. Если он сообщает, что точка входа DllRegisterServer не найдена, не пытайтесь исправить это новыми командами: MSVCP110.dll и MSVCR110.dll следует возвращать официальным пакетом. Не скачивайте «DLL fixer» и не меняйте права системных папок ради копирования.
