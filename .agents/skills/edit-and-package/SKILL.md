# Отредактировать и подготовить черновик

Применять на соответствующем этапе координатора article-workflow, в том числе при возврате после ошибки. Прочитать общую [политику](../../../editorial/policy.md) и [контракты](../../../editorial/contracts.md).

## Вход
Проверенный текст и артефакты.
## Действия
Два прохода itpotok-writing: структура, язык; сохранить фактический смысл; проверить ссылки, alt, права, обложку, FAQ и зависимости ID. После смысловой правки вернуть проверку. Запустить check; сохранить preview.html; при доступе сохранить WordPress draft и проверить шаблон широкий/узкий; сверить тело и отрывок API; обновить README и GitHub. Публикация — отдельное явное поручение.
## Инструменты
Python workflow.py, Git, авторизованный WordPress API/штатный UI, браузер. Проверить наличие и разрешения в текущей сессии; перечисление инструмента не создаёт интеграцию.
## Результат
preview.html, package-report.json, README.md, faq.md. Сохранить в папке статьи; контрольную точку — в workflow.json через команду checkpoint. Не заменять предыдущие свидетельства: новые прогоны получают отдельный ID.
## Качество
Границы проверки честны; локальный preview не выдаётся за проверку темы сайта.
## Остановка
check не прошёл или нет обязательного кадра — черновик не ready; сбой GitHub явно сообщить.
## Примеры
Хорошо: README содержит ID черновика, ветку и непроверенный узкий экран.

Плохо: Файл в медиатеке объявлен установленной обложкой без проверки.
