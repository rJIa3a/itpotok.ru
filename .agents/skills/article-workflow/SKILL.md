# Координатор редакционного процесса

При новой статье или полной переработке сначала прочитать ../../../editorial/policy.md, ../../../editorial/contracts.md и ../../../editorial/README.md. Применимые AGENTS.md сохраняют силу. Для узкой языковой правки достаточно itpotok-writing; не запускать весь процесс.

Вход: ключ, конкурент и контекст проекта; неизвестное исследовать, выбор нескольких существующих записей уточнить. Создать отдельную ветку и папку с README командой init. Для существующей записи сначала сохранить исходную версию, ID и URL; не перезаписывать её инициализатором.

Один координатор последовательно читает только нужный ../<этап>/SKILL.md и сохраняет результат. Отдельный агент на навык не нужен.

Информационная статья и сравнение: article-brief → research → claim-ledger → outline → draft → visuals → fact-and-procedure-check → edit-and-package.

Мануал: article-brief → research/claim-ledger для условий → procedure-runner → screenshot-capture → outline → draft → visuals по необходимости → fact-and-procedure-check с повторным выполнением по тексту → edit-and-package.

Перед checkpoint проверить артефакты и кратко записать вывод; команда хранит хеши. После изменения предыдущего этапа вернуться к первой устаревшей точке. check не доказывает истинность источников: координатор должен открыть их и проверить покрытие существенных утверждений. Остановка: отсутствующие доступы или доказательства оставляют unverified-draft и перечень задач, не останавливают независимое исследование. Публикация запрещена без отдельного поручения.

Результат: папка по контракту, локальный предпросмотр, ссылки на WordPress draft и GitHub при доступе, краткие границы проверки. После срока сверки использовать ../refresh/SKILL.md.

Хорошо: после исправления шага повторить прогон текущего текста. Плохо: отметить все этапы готовыми по наличию файлов.
