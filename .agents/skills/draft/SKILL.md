# Написать материал по доказательствам

Применять на соответствующем этапе координатора article-workflow, в том числе при возврате после ошибки. Прочитать общую [политику](../../../editorial/policy.md) и [контракты](../../../editorial/contracts.md).

## Вход
Бриф, план, claims, журнал.
## Действия
Прочитать itpotok-writing и нужные references; писать только в пределах доказательств; связывать существенные абзацы с claim ID через data-claims; в мануале сохранить действия, названия и ожидания. Пробелы записать в review.md, существенные ограничения — в текст.
## Инструменты
Редактор HTML, itpotok-writing. Проверить наличие и разрешения в текущей сессии; перечисление инструмента не создаёт интеграцию.
## Результат
article.html, excerpt.txt, review.md. Сохранить в папке статьи; контрольную точку — в workflow.json через команду checkpoint. Не заменять предыдущие свидетельства: новые прогоны получают отдельный ID.
## Качество
Один текущий исходник; нет выдуманного опыта; внешний источник rel=nofollow.
## Остановка
Нет основания для существенного ответа — оставить unverified-draft.
## Примеры
Хорошо: По справке способ применим при указанных условиях.

Плохо: Гарантируем результат на всех устройствах.
